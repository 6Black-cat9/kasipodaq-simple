# КӘСІПОДАҚ — простая версия

Рабочая платформа школьного профсоюза с интерфейсом на казахском языке. Обычные HTML, CSS и JavaScript в браузере; PHP 8.2+ и SQLite на сервере. Данные сохраняются в базе, файлы — в закрытой папке. Вход через защищённые PHP-сессии, пароли хешируются bcrypt.

**Не нужны React, Vite, Node.js, npm, PostgreSQL, Prisma, JWT или сборка приложения.** База создаётся автоматически при первом открытии. Эта версия независима от прежнего проекта: существующая PostgreSQL-база автоматически не переносится.

## Быстрый запуск на хостинге

1. Выберите обычный PHP-хостинг с **PHP 8.2 или новее, PDO_SQLite, Fileinfo и Apache/LiteSpeed с поддержкой `.htaccess`**. Для демонстрации ваш небольшой тариф подходит, **если хостер поддерживает эти расширения**. 1 ГБ диска достаточно для проекта и небольшого количества документов; точный расход зависит от загружаемых файлов.
2. Распакуйте архив. Загрузите **содержимое папки `kasipodaq-simple` целиком**, включая скрытые `.htaccess`, в `public_html` через файловый менеджер или FTP. Не загружайте ZIP вместо распакованных файлов. Папка `storage` должна быть доступна на запись процессу PHP.
3. Откройте адрес сайта. Он перенаправит на `/public/`. Создайте администратора: имя, фамилия, email и свой пароль. Для показа оставьте галочку демо данных.
4. Войдите под созданным администратором. Меню кабинета содержит все разделы управления.
5. Включите HTTPS в панели хостинга. Не меняйте права папок на `777`: попросите хостера настроить владельца и запись для PHP.

Если хостинг позволяет выбирать корневую папку сайта, укажите `kasipodaq-simple/public`: это предпочтительный вариант. Остальные папки тогда находятся вне публичного доступа. На Nginx **обязательно** используйте этот вариант: Nginx не читает `.htaccess`.

На GitHub Pages PHP не выполняется. Репозиторий GitHub хранит исходники, для работы сайта нужен PHP-хостинг.

## Локальный запуск

Установите PHP 8.2+ с расширениями `pdo_sqlite`, `fileinfo`, `session`, `json` (обычно входят в PHP), затем в папке проекта выполните:

```bash
php -d upload_max_filesize=10M -d post_max_size=12M -S localhost:8080 -t public public/router.php
```

Откройте `http://localhost:8080` и пройдите первоначальную установку. Один сервер обслуживает и интерфейс, и API. Отдельных frontend/backend-команд, миграций и ручного seed не требуется. `app/schema.sql` создаётся автоматически; галочка на первом экране запускает `app/seed.php`.

На Windows удобно установить PHP через готовую локальную PHP-среду. При отсутствии `PDO_SQLite` включите `extension=pdo_sqlite` в `php.ini` и перезапустите PHP.

## Возможности

- Публичная главная, новости и подробности, документы с поиском/категориями/просмотром PDF/скачиванием, предстоящие и прошлые мероприятия с подробностями.
- Вход и выход, кабинет, профиль и фото, смена пароля, уведомления и количество непрочитанных.
- Члены: поиск по ФИО, фильтры по отделу, должности и статусу, пагинация, создание, просмотр, изменение, удаление, активность.
- Заявки: четыре вида, сумма, вложения, создание/просмотр/редактирование/удаление, шесть статусов, комментарии, ответы, история изменений. Член видит только свои заявки. После начала рассмотрения член не может редактировать или удалять заявку.
- Новости: CRUD, slug, фото, черновики/публикация, отправка уведомлений при сохранении опубликованной новости.
- Документы: CRUD, семь категорий, безопасное сохранение PDF/DOC/DOCX/XLS/XLSX/JPG/PNG до 10 МБ, проверка расширения, MIME и сигнатуры.
- Мероприятия: CRUD, даты, время, организатор, место, изображения, статус, запись и отмена записи участника.
- Dashboard: реальные показатели, последние заявки/члены/новости, ближайшие мероприятия.
- Статистика: показатели и пять диаграмм по членам, заявкам, видам, статусам и мероприятиям; 7/30/90/180/365 дней. Фильтр меняет диаграммы, карточки показывают общие текущие показатели.
- Управление пользователями, ролями и доступом; настройки школы и важной информации.
- Адаптивный интерфейс, мобильное меню, таблицы с горизонтальной прокруткой внутри блока, проверки форм, загрузка, пустые состояния, ошибки, toast, подтверждение удаления, клавиатура, reduced-motion.

### Права

| Раздел | ADMIN | CHAIRMAN | MEMBER |
|---|---|---|---|
| Члены | CRUD | Просмотр | Нет |
| Заявки | Все, статусы/ответы | Все, статусы/ответы | Только свои |
| Новости/мероприятия | CRUD | CRUD | Просмотр; участие |
| Документы | CRUD | Просмотр | Просмотр |
| Статистика | Да | Да | Нет |
| Пользователи/настройки | Да | Нет | Нет |
| Профиль/уведомления | Свои | Свои | Свои |

Удаление связанных записей, например члена с заявками или автора опубликованных материалов, отклоняется с HTTP 409. Для сохранения истории используйте «Белсенді емес» или отключите аккаунт, а не удаляйте его. Собственный аккаунт администратора нельзя удалить, отключить или лишить роли ADMIN. В системе всегда остаётся хотя бы один активный администратор.

## Конфигурация

Приложение работает с `config.example.php` без дополнительных настроек. При необходимости скопируйте его в `config.php` и измените путь хранения, лимит файлов или длительность сессии. `config.php` и содержимое `storage` исключены из Git. Внешних секретов, JWT-ключей и паролей базы не требуется.

Переменная окружения `KASIPODAQ_STORAGE` переопределяет папку хранения: полезна для изолированных тестов. В обычном запуске не нужна. Пример настройки:

```php
<?php
return [
    'storage' => __DIR__ . '/storage',
    'max_upload_bytes' => 10 * 1024 * 1024,
    'session_hours' => 8,
];
```

Лимиты PHP `upload_max_filesize` и `post_max_size` должны быть не меньше 10M и 12M. В архив включён `public/.user.ini`. После изменения настроек на хостинге может потребоваться несколько минут.

## Безопасность и хранение

SQL выполняется подготовленными запросами PDO. Изменения проходят транзакции SQLite. Сервер проверяет роль и владельца каждой заявки/вложения. Изменяющие запросы требуют CSRF-токен, сессии используют HttpOnly/SameSite и Secure при HTTPS. Вход ограничен 20 попытками за 15 минут на IP. Смена роли, активности или пароля делает старые сессии недействительными. Пароли и хеши не возвращаются API.

Содержимое пользовательских полей отображается как текст, а не HTML. HTML/скрипты не принимаются как загружаемые файлы. Загрузки сохраняются вне `public`, исполняемые имена файлов не используются. Файлы заявок доступны владельцу и администрации; документы и обложки опубликованных материалов — публичны. Файлы удалённых записей остаются в закрытом хранилище для сохранности; учитывайте это при контроле места на диске.

SQLite хорошо подходит для демонстрации и небольшого школьного портала. Данные сохраняются на диске хостинга; такой сайт нельзя размещать на платформе, удаляющей локальный диск при перезапуске.

### Резервная копия

Остановите доступ к сайту на время копирования, затем сохраните **всю папку `storage`**, включая базу, `-wal`/`-shm` при их наличии и `uploads`. Храните копию вне публичной папки. Для восстановления при остановленном приложении восстановите эту папку и права владельца. Архив исходников не содержит пользовательских данных и не заменяет резервную копию.

## API

Документация: [docs/API.md](docs/API.md). Полная OpenAPI 3.1 спецификация: [public/openapi.json](public/openapi.json). На работающем сайте откройте `api-docs.html` в публичной папке.

Основной адрес без требований к rewrite: `api.php?path=...`. Например `api.php?path=auth/login`. С Apache mod_rewrite или встроенным роутером также доступны `/api/auth/login`, `/api/members`, `/api/applications` и остальные REST-адреса.

Успешный ответ: `{"success":true,"message":"...","data":{}}`.
Ошибка: `{"success":false,"message":"...","errors":[]}`.

## Проверки

34 интеграционных тестов: вход, права и владение, создание члена и заявки, изменение статуса/история, CRUD новостей/документов/мероприятий, MIME, CSRF, SQL-инъекция, уведомления, защита администратора, профиль, пароль, статистика, установка. Дополнительно браузерные сценарии проверяют реальные формы, файлы, кабинет, админ-панель и мобильную ширину. PHP синтаксис проверяется для всех PHP-файлов.

Тесты используют **отдельную пустую папку данных**, чтобы не затрагивать настоящий сайт. Python/Node нужны только разработчику для тестов:

```bash
# Терминал 1, папка должна быть новой и доступной PHP:
KASIPODAQ_STORAGE=/tmp/kasipodaq-tests php -d upload_max_filesize=10M -d post_max_size=12M -S localhost:8081 -t public public/router.php

# Терминал 2:
TEST_URL=http://localhost:8081/ python3 tests/api_test.py
```

Тесты устанавливают демо с `admin@example.com` / `Dev@12345!`. Для повторной проверки используйте новую пустую папку данных. Браузерные проверки можно запускать после API-тестов, установив Playwright в отдельном окружении тестов:

```bash
npm install --no-save playwright
npx playwright install chromium
TEST_URL=http://localhost:8081/ node tests/browser.mjs
TEST_URL=http://localhost:8081/ node tests/browser-management.mjs
```

Приложению эти команды не требуются. При необходимости исходники проверяются ESLint по `eslint.config.mjs`; правила: no-undef, no-unused-vars и eqeqeq. Настройки редактора и Prettier включены в проект.

Снимки тестов сохраняются в `tests/artifacts`; пути браузера и снимков можно задать `CHROMIUM_PATH` и `SHOT_DIR`.

## GitHub и обновление

Загрузите исходники в репозиторий через Git или «Add file → Upload files». Перед commit убедитесь, что `config.php` и данные `storage` отсутствуют среди добавленных файлов. Не публикуйте базу, сессии или пользовательские документы.

Перед обновлением сохраните резервную копию. Обновляйте исходники, сохраняя `storage` и свой `config.php`. Для текущей версии база создаётся автоматически из `app/schema.sql`; отдельный инструмент миграций не требуется.

Демо фотографии сохранены локально из Unsplash; PDF — учебные образцы, их можно заменить официальными документами школы. Лицензия шрифта Noto Sans находится в `public/assets/fonts/OFL.txt`.
